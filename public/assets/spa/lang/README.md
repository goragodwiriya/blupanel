# ไฟล์ภาษาของ SPA

## ทำไม `en.json` ถึงว่าง

Now.js ตั้ง `noTranslateEnglish: true` ไว้เป็นค่าเริ่มต้น ซึ่งแปลว่า **ข้อความต้นทาง
ในเทมเพลตคือคีย์แปลไปในตัว** — เมื่อผู้ใช้เลือกภาษาอังกฤษ เฟรมเวิร์กจะใช้ข้อความในเทมเพลต
ตรง ๆ โดยไม่เปิดไฟล์ `en.json` เลย

`en.json` จึงมีอยู่เพื่อให้โครงไฟล์ครบและเผื่อวันที่ต้องแก้คำอังกฤษบางคำโดยไม่แตะเทมเพลต
ไม่ใช่ไฟล์ที่ลืมเติม

## กฎการเขียนข้อความ

1. **เขียนภาษาอังกฤษในเทมเพลต แล้วแปลไทยใน `th.json`** — สลับทางไม่ได้ เพราะคีย์คือ
   ข้อความอังกฤษ
2. **`data-i18n` ต้องมีคีย์เขียนกำกับเสมอ** เช่น `data-i18n>Domain<`
   ห้ามปล่อยว่าง · `TableManager` ฉีด `<span class="col-resizer">` เข้าไปใน `<th>`
   ก่อน i18n ทำงาน ทำให้โหมดเดาคีย์จากเนื้อในพัง อาการคือหัวตารางไม่ถูกแปล
   ทั้งที่ป้ายอื่นในหน้าเดียวกันแปลปกติ
3. **ข้อความในไฟล์ `js/*.js` ต้องห่อด้วย `t()`** ซึ่งเรียก `Now.translate()` ให้
4. เรียงคีย์ตามตัวอักษรแบบไม่สนตัวพิมพ์ เพื่อให้ diff อ่านง่ายและหาซ้ำเจอ

## ตรวจว่ามีคีย์ตกหล่นไหม

รันจาก `public/app/`

```bash
# คีย์ที่เทมเพลตใช้แต่ th.json ไม่มี
grep -ho 'data-i18n="[^"]*"' templates/*.html \
  | sed 's/data-i18n="//; s/"$//' | sort -u \
  | while read -r key; do
      grep -q "\"$key\":" lang/th.json || echo "ขาด: $key"
    done

# คีย์ที่โค้ด JS ใช้แต่ th.json ไม่มี
# (ต้องมี lookbehind กันไม่ให้จับ Api().get('/session') ซึ่งลงท้ายด้วย t('...') เหมือนกัน)
grep -hoP "(?<![\w.])t\('([^']*)'\)" js/*.js \
  | sed "s/^t('//; s/')$//" | sort -u \
  | while read -r key; do
      grep -q "\"$key\":" lang/th.json || echo "ขาด: $key"
    done
```

ทั้งสองคำสั่งต้องไม่พิมพ์อะไรออกมาเลย
