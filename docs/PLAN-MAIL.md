## 1. ขอบเขตที่ตกลงแล้ว

| ทำใน v1 (M1–M3) | ไม่ทำใน v1 |
|---|---|
| รับเมลเข้ากล่องจริง (MX → Postfix → Dovecot → Maildir) | เว็บเมล — ผู้ใช้ต่อ IMAP ด้วยโปรแกรมของตัวเอง |
| อ่านเมลผ่าน IMAP/POP3 บน TLS | ปฏิทิน/สมุดที่อยู่ (CalDAV/CardDAV) |
| ส่งเมลผ่าน submission (587/465) ด้วยรหัสของกล่อง | รายการส่งเมลกลุ่ม (mailing list) |
| สร้าง/ลบ/ตั้งรหัส/ตั้งโควตากล่องบนแผงควบคุม | ลายเซ็น/กฎกรองรายบุคคล (Sieve) — เลื่อนไป M4 |
| alias · forwarder · catch-all | ClamAV — เลื่อนไป M4 (กิน RAM ~1GB) |
| DKIM/SPF/DMARC/MX สร้างอัตโนมัติตอนเปิดเมลให้โดเมน | ย้ายเมลเข้าจากผู้ให้บริการเดิม (IMAP migration) |
| หน้าตรวจความพร้อมของเมล (6 ข้อ) | |
| ขาออกเลือกได้ระหว่างส่งตรงกับผ่าน relay | |

**เมลขาออกรองรับสองทางเลือกได้เสมอ** — เครื่องที่ผู้ให้บริการบล็อกพอร์ต 25 ขาออก (AWS, GCP,
Azure, DigitalOcean เป็นค่าเริ่มต้น) ยังใช้ระบบนี้ได้เต็มรูปแบบโดยส่งผ่าน relay ภายนอก
ส่วนการ**รับ**เมลไม่ได้พึ่งพอร์ต 25 ขาออก จึงทำงานได้ทุกกรณี

## 2. สามอย่างที่โค้ดแก้ให้ไม่ได้

เขียนไว้ตรงนี้เพราะเป็นเหตุผลเดิมที่ PLAN-V2 ตัดเมลออก — ไม่ได้หายไป แค่ย้ายจาก
"เหตุผลที่ไม่ทำ" มาเป็น "สิ่งที่ระบบต้องบอกผู้ดูแลให้ชัด"

1. **rDNS/PTR ตั้งได้ที่ผู้ให้บริการ VPS เท่านั้น** — ไม่ตรงกับ mail hostname เมื่อไหร่
   ปลายทางหลายเจ้าตีเป็นสแปมทันที · panel **ตรวจให้และเตือนได้ แต่ตั้งให้ไม่ได้**
2. **พอร์ต 25 ขาออกมักถูกบล็อก** — ต้องยื่นขอปลดกับผู้ให้บริการ หรือใช้ relay
3. **IP ใหม่ไม่มีชื่อเสียง** — ช่วงแรกเมลเข้า junk ของ Gmail/Outlook เป็นเรื่องปกติ
   ต้องส่งทีละน้อยเพื่ออุ่นเครื่อง

**ข้อสรุปเชิงออกแบบ:** ระบบต้องไม่แกล้งทำเป็นว่าสามข้อนี้ไม่มีอยู่ · หน้าความพร้อมของเมล
(§7) คือคำตอบ — บอกตรง ๆ ว่าอะไรพร้อม อะไรยังไม่พร้อม และข้อไหนต้องไปทำที่อื่น

## 3. สถาปัตยกรรม

```
อินเทอร์เน็ต ──25──►  Postfix  ──LMTP──►  Dovecot  ──►  Maildir
             ──587/465──►  (smtpd)  ──SASL──►  (auth)      /srv/phpcp/mail/<โดเมน>/<ชื่อ>/
             ──993/995──────────────────────►  (imap/pop3)
                              ▲
                              │ milter
                           rspamd  — กรองสแปม + เซ็น DKIM ในตัวเดียว
```

### 3.1 การตัดสินใจเชิงสถาปัตยกรรม

| # | ตัดสินว่า | เหตุผล |
|---|---|---|
| **M-A** | **กล่องจดหมายเป็น virtual mailbox** เจ้าของไฟล์คือผู้ใช้ระบบ `vmail` คนเดียว | ไม่มีบัญชี Linux เพิ่มต่อหนึ่งกล่อง · ไม่มี shell · กล่อง 500 กล่องไม่ทำให้ `/etc/passwd` บวม และไม่กลายเป็นทางเข้าเครื่อง |
| **M-B** | **ตารางค้นหาเป็นไฟล์ที่ระบบ generate** (`hash:` ของ Postfix + `passwd-file` ของ Dovecot) ไม่ใช่ให้เดมอนอ่าน SQLite ของ panel ตรง ๆ | เข้ากับ `ConfigTransaction` ที่มีอยู่ (เขียน → ตรวจ → ย้อนกลับพร้อมกัน) · agent ยังเป็นผู้เขียนไฟล์ตั้งค่าคนเดียวของทั้งระบบ · ไม่ต้องเปิดสิทธิ์อ่านฐานข้อมูล panel ให้เดมอนอื่น · ทางเลือก `sqlite:` map ต้องลง `postfix-sqlite` และเจอ lock ตอนโหลดสูง |
| **M-C** | **rspamd ตัวเดียว** แทน SpamAssassin + OpenDKIM + policyd | เดมอนเดียวทำครบทั้งกรองสแปม เซ็น DKIM และจำกัดอัตรา — สามอย่างที่เดิมต้องสามโปรแกรม สามไฟล์ตั้งค่า สามจุดที่พังได้ |
| **M-D** | **รหัสผ่านกล่องเก็บเป็นแฮชเท่านั้น** (ARGON2ID ของ Dovecot) แสดงครั้งเดียวตอนสร้าง | แบบเดียวกับรหัสฐานข้อมูล · panel ที่เก็บรหัสเมลแบบถอดกลับได้คือฐานข้อมูลรหัสผ่านที่รอวันรั่ว |
| **M-E** | **เปิดเมลเป็นรายโดเมน ไม่ใช่เปิดทั้งเครื่อง** | โดเมนที่ไม่ได้ใช้เมลต้องไม่มี MX ชี้มา และไม่ต้องมีอะไรใน virtual maps |
| **M-F** | **ไม่มี plaintext IMAP/POP3** — ปิด 110/143 เสมอ เหลือแต่ 993/995 และ submission ที่บังคับ TLS | รหัสผ่านเมลวิ่งผ่านเน็ตทุกครั้งที่โปรแกรมเมลเช็คกล่อง (ทุกไม่กี่นาที) |
| **M-G** | **โควตาสองชั้น**: จำนวนกล่องต่อบัญชี (`quota_emails` ที่มีอยู่แล้ว) + ขนาดต่อกล่อง (Dovecot quota) | ช่องโควตาที่มีอยู่ในหน้าลูกค้าจะได้มีระบบจริงอยู่หลังเสียที (ตอนนี้ `QuotaChecker` ฮาร์ดโค้ด `$emails = 0`) |

### 3.2 ที่เก็บไฟล์

```
/srv/phpcp/mail/<โดเมน>/<ชื่อกล่อง>/     Maildir ของแต่ละกล่อง (เจ้าของ vmail:vmail 0700)
/etc/postfix/vmailbox                    hash map: อีเมล → เส้นทาง Maildir
/etc/postfix/valias                      hash map: alias/forwarder/catch-all
/etc/postfix/vdomains                    รายชื่อโดเมนที่เครื่องนี้รับเมลให้
/etc/dovecot/phpcp-users                 passwd-file: อีเมล + แฮชรหัสผ่าน + โควตา
/etc/dovecot/conf.d/99-phpcp.conf        ค่าที่ panel เป็นเจ้าของทั้งไฟล์
/var/lib/rspamd/dkim/<โดเมน>.key         กุญแจส่วนตัวของ DKIM (0640 rspamd)
```

ทุกไฟล์ในรายการนี้ **ระบบเขียนใหม่ทั้งไฟล์เสมอ** ไม่มีการแก้ทีละบรรทัด — หัวไฟล์เขียนกำกับว่า
สร้างโดย panel ห้ามแก้ด้วยมือ เหมือน vhost และ `ports.conf`

## 4. ข้อมูลในฐานข้อมูล

```sql
CREATE TABLE mailboxes (
    id            INTEGER PRIMARY KEY,
    domain_id     INTEGER NOT NULL REFERENCES domains(id) ON DELETE CASCADE,
    local_part    TEXT    NOT NULL,          -- ส่วนหน้า @
    password_hash TEXT    NOT NULL,          -- {ARGON2ID}... ของ Dovecot
    quota_mb      INTEGER NOT NULL DEFAULT 1024,
    enabled       INTEGER NOT NULL DEFAULT 1,
    created_at    INTEGER NOT NULL,
    UNIQUE (domain_id, local_part)
);

CREATE TABLE mail_aliases (
    id          INTEGER PRIMARY KEY,
    domain_id   INTEGER NOT NULL REFERENCES domains(id) ON DELETE CASCADE,
    source      TEXT    NOT NULL,            -- ว่าง = catch-all ของโดเมนนี้
    destination TEXT    NOT NULL,            -- คั่นด้วยจุลภาคได้หลายปลายทาง
    created_at  INTEGER NOT NULL,
    UNIQUE (domain_id, source)
);
```

เจ้าของกล่องคือเจ้าของโดเมน ซึ่งมาจาก `domains.site_id → sites.owner_user_id` ที่มีอยู่แล้ว —
ไม่มีแนวคิด "เจ้าของกล่อง" แยกต่างหากให้ต้องดูแลให้ตรงกันอีกชุด

**การเปิดเมลของโดเมน** เก็บเป็นแถวใน `settings` ต่อโดเมน หรือคอลัมน์ `mail_enabled` ใน
`domains` — เลือกอย่างหลังเพราะเป็นคุณสมบัติของโดเมนตรง ๆ และ query ง่ายกว่า

## 7. หน้าความพร้อมของเมล

ตรวจหกข้อ แล้วบอกว่าข้อไหน panel แก้ให้ได้ ข้อไหนต้องไปทำที่อื่น:

| ข้อ | ตรวจยังไง | ถ้าไม่ผ่าน |
|---|---|---|
| MX ชี้มาที่เครื่องนี้ | `dig MX` เทียบกับ IP ของเครื่อง | panel เพิ่มให้ได้ถ้าโดเมนใช้ DNS ของเครื่องนี้ |
| rDNS/PTR ตรงกับ mail hostname | `dig -x <ip>` | **ต้องไปตั้งที่ผู้ให้บริการ VPS** |
| SPF/DKIM/DMARC ครบ | `dig TXT` ทั้งสามชื่อ | panel เพิ่มให้ได้ |
| พอร์ต 25 ขาออกใช้ได้ | ต่อ TCP ไปที่ MX ของ gmail.com | สลับไปโหมด relay |
| IP ไม่ติดบัญชีดำ | ถาม DNSBL หลัก (Spamhaus ฯลฯ) | ต้องยื่นถอดกับเจ้าของบัญชีดำ |
| ใบรับรองของ mail hostname ใช้ได้ | อ่านวันหมดอายุจากไฟล์ | ปุ่มขอใบรับรองที่มีอยู่แล้ว |

- [x] `main.cf`/`master.cf` มีโหมด "รับเมล" ที่เปิดเฉพาะเมื่อมีโดเมนเปิดเมลจริง
- [x] เปิดพอร์ต 25/465/587/993/995 ตอนติดตั้ง

- [x] capability `mail.domain_set` · `mail.box_create` · `mail.box_delete` + สิทธิ์ `mail.view`/`mail.manage`
- [x] CLI: `mail:enable` · `mail:disable` · `mail:box-add` · `mail:box-del` · `mail:list`
- [ ] ใบรับรองของ mail hostname ผ่าน certbot — **ยกไป M3** (ตอนนี้ใช้ใบของดิสโทรไปก่อน
      ซึ่งใช้งานได้แต่โปรแกรมเมลจะเตือนเรื่องใบรับรอง)

**สามบั๊กที่เจอเพราะยิงจริง ไม่มีทางเจอจากเทสต์ในโปรเซส:**

1. `systemctl restart` ของสองเดมอนช้าเกิน 30 วินาทีที่ agent รอ — คำสั่งเมลทุกคำสั่ง
   ล้มด้วย "agent ไม่ตอบกลับ" · เปลี่ยนมาใช้ `postfix reload`/`doveadm reload` ที่เสร็จ
   ในเสี้ยววินาทีและไม่ตัดการเชื่อมต่อที่ใช้งานอยู่
2. ไฟล์ผู้ใช้เป็นของ `root:root` 0640 — Dovecot อ่านไม่ได้ ได้ "Temporary authentication
   failure" ตอนล็อกอิน และเมลถูกตีกลับ · ทั้งสองข้อความไม่มีคำว่า permission เลย
3. โฟลเดอร์ของ**โดเมน** ถูกสร้างเป็นของ root (mkdir -p) ทั้งที่โฟลเดอร์ของกล่องถูกต้อง —
   Dovecot เดินผ่านเข้าไปไม่ได้ เมลตีกลับด้วย "Temporary internal error"

4. **`postfix reload` เปลี่ยนพอร์ตที่ฟังไม่ได้ ต้อง restart** — เจอตอนติดตั้งบนเครื่องจริง
   (ไม่เจอในคอนเทนเนอร์เพราะที่นั่นสตาร์ต Postfix หลังเขียน config เสมอ) · `main.cf`
   เขียนว่า `inet_interfaces = all` แต่ Postfix ยังฟังแค่ 127.0.0.1 อยู่ แปลว่า
   **เมลจากอินเทอร์เน็ตไม่มีทางถึงเครื่องเลย** และไม่มีอะไรฟ้องเพราะไฟล์ถูกต้องหมด ·
   ตระกูลเดียวกับบั๊ก `ports.conf` ของ Apache ที่เจอก่อนหน้านี้: ไฟล์ถูก เดมอนไม่ทำตาม

**และสองบั๊กในตัวเทสต์เอง:** ทดสอบ open relay จาก 127.0.0.1 ซึ่ง `permit_mynetworks`
อนุญาตอยู่แล้วโดยตั้งใจ — ผ่านเสมอไม่ว่าค่าตั้งจะถูกหรือผิด · ตอนนี้ยิงจากที่อยู่จริง
ของเครื่อง และแยก "ต่อไม่ได้" ออกจาก "เป็น open relay" ให้ชัด · และ `hostname -i` บน
Ubuntu คืน `127.0.1.1` ซึ่งยังเป็น loopback — ต้องใช้ที่อยู่ scope global จริง

เพิ่มการตรวจข้อใหม่: **หลังเปิดเมลต้องฟังพอร์ต 25 จากภายนอกจริง** ไม่ใช่แค่ไฟล์เขียนว่าฟัง

### M2 — จัดการบนแผงควบคุม

- [ ] migration: `mailboxes` · `mail_aliases` · `domains.mail_enabled`
- [ ] capability ทั้งเก้าตัวใน §5 + สิทธิ์ `mail.view`/`mail.manage` ใน `Permissions`
- [ ] API + หน้า `/mailboxes` + ฟอร์มใน Modal
- [ ] ต่อ `QuotaChecker` ให้นับกล่องจริง (เลิกฮาร์ดโค้ด `$emails = 0`)
- [ ] ลบโดเมน/เว็บไซต์ต้องลบกล่องและไฟล์ตามไปด้วย (มี confirm ที่บอกจำนวนเมลที่จะหาย)
- [ ] **เกณฑ์ผ่าน:** สร้างกล่องจากหน้าเว็บแล้วรับเมลได้ทันทีโดยไม่ต้องแตะ CLI ·
      ลูกค้าเห็นเฉพาะกล่องของโดเมนตัวเอง · โควตาเต็มแล้วสร้างเพิ่มไม่ได้

### M3 — ส่งถึงจริง

- [ ] rspamd + เซ็น DKIM ต่อโดเมน (สร้างกุญแจตอนเปิดเมล)
- [ ] เพิ่ม MX/SPF/DKIM/DMARC ลง zone อัตโนมัติผ่าน `BindZoneManager` ที่มีอยู่
- [ ] หน้าความพร้อมของเมล (§7) + `mail.readiness`
- [ ] โหมดขาออก: ส่งตรง / ผ่าน relay เลือกได้จากหน้าตั้งค่า (ต่อยอด `MailManager` เดิม)
- [ ] **เกณฑ์ผ่าน:** ส่งเมลออกไป Gmail แล้วเข้ากล่องหลัก (ไม่ใช่ junk) พร้อมผ่าน SPF+DKIM+DMARC
      ตรวจจาก header ของเมลที่ปลายทางได้จริง

## 9. ความปลอดภัย — กฎที่ห้ามพลาด

| กฎ | บังคับด้วยอะไร |
|---|---|
| **ห้ามเป็น open relay** | `smtpd_relay_restrictions` แน่นอน + **เทสต์ที่ยิงจริงในชุดทดสอบทุกครั้ง** |
| ส่งออกต้องล็อกอินเสมอ (587/465) | `smtpd_sasl_auth_enable` + `permit_sasl_authenticated, reject` |
| กล่องหนึ่งอ่านไฟล์ของอีกกล่องไม่ได้ | Maildir 0700 เจ้าของ vmail · Dovecot จำกัดที่ home ของแต่ละกล่อง |
| รหัสผ่านไม่วิ่งเป็น plaintext | ปิด 110/143 · submission บังคับ STARTTLS |
| เดารหัสผ่านไม่ได้ไม่จำกัด | fail2ban jail ของ dovecot/postfix (M4) + `smtpd_client_*_limit` |
| ส่งสแปมออกจากกล่องที่ถูกยึดไม่ได้ | จำกัดอัตราส่งต่อกล่องด้วย rspamd (M4) + แจ้งเตือนเมื่อเกิน |
| ชื่อกล่อง/โดเมนที่ผู้ใช้กรอกไม่กลายเป็นคำสั่ง | `Validator` เดิม + ไม่มีที่ไหนต่อสตริงเป็น shell (กฎเดิมของทั้งระบบ) |

## 10. การทดสอบ

**ในคอนเทนเนอร์** (เข้าชุดกับ `docker/acceptance*.sh` ที่มีอยู่):
ส่งเมลเข้ากล่องด้วย `swaks` แล้วอ่านออกมาทาง IMAP · open relay ต้องถูกปฏิเสธ ·
ล็อกอินผิดซ้ำต้องโดนบล็อก · โควตาเต็มต้องปฏิเสธเมลใหม่ (ไม่ใช่รับแล้วทิ้งเงียบ ๆ) ·
ลบโดเมนแล้วไฟล์เมลต้องหายจริง · `postfix check` และ `doveconf -n` ต้องผ่านหลังทุกคำสั่ง

**บนเครื่องจริง** (ทำไม่ได้ในคอนเทนเนอร์): ส่งออกไป Gmail/Outlook แล้วดู header ว่า
SPF/DKIM/DMARC ผ่าน · rDNS ตรง · เมลเข้ากล่องหลักไม่ใช่ junk

## 11. ความเสี่ยง

| ความเสี่ยง | ผลถ้าเกิด | จัดการ |
|---|---|---|
| ตั้ง relay ผิดจนเป็น open relay | IP ติดบัญชีดำถาวร กระทบ**ทุกเว็บ**บนเครื่อง | เทสต์ open relay เป็นเทสต์บังคับ ไม่ใช่ทางเลือก |
| กล่องถูกยึดแล้วใช้ส่งสแปม | เหมือนข้างบน | จำกัดอัตราส่งต่อกล่อง + แจ้งเตือนเมื่อผิดปกติ (M4) |
| Maildir กินดิสก์จนเต็ม | ทุกบริการบนเครื่องล้ม | โควตาต่อกล่องบังคับเสมอ + เกณฑ์เตือนดิสก์ที่มีอยู่แล้ว |
| ลบโดเมนแล้วเมลหายโดยไม่ตั้งใจ | ข้อมูลลูกค้าหาย | ต้องยืนยันพร้อมบอกจำนวนกล่อง + ให้สำรองก่อนใน M6 |
| RAM ไม่พอ (rspamd ~200MB) | บริการอื่นถูก OOM kill | เอกสารระบุขั้นต่ำ 2GB สำหรับเครื่องที่เปิดเมล |
