$ cd blupanel
$ sudo ./install.sh

Features

ครบทุกงานของเซิร์ฟเวอร์โฮสติ้ง

จากการสร้างเว็บไซต์แรก ไปจนถึงการดูแลระบบทั้งเครื่อง — ทำได้ครบจากเบราว์เซอร์ ไม่ต้อง SSH เข้าไปแก้ config ด้วยมือ

เว็บไซต์

สร้าง พัก ลบเว็บไซต์ — เลือก Apache, nginx หรือ nginx+Apache (ใช้ .htaccess บน nginx ได้) พร้อม PHP หลายเวอร์ชันต่อเว็บ และ Domain Pointer

ฐานข้อมูล

สร้างฐานข้อมูล ผู้ใช้ และสิทธิ์บน MariaDB · เข้า phpMyAdmin ต่อจาก panel ได้ทันทีโดยไม่ต้องพิมพ์รหัสผ่าน

SSL อัตโนมัติ

ขอใบรับรอง Let's Encrypt ทั้งแบบ webroot และ DNS-01 สำหรับ wildcard · รองรับ self-signed · ต่ออายุอัตโนมัติ

โดเมนและ DNS

โดเมนหลัก โดเมนย่อย alias และ wildcard — เขียน zone เข้า BIND9 ของจริง พร้อมตรวจ named-checkzone ทุกครั้งก่อนใช้

ผู้ใช้โฮสติ้ง

หนึ่งบัญชี = หนึ่ง uid = หนึ่งบ้าน — ลูกค้าแยกจากกันจริง · โควตาโดเมน/ฐานข้อมูล/อีเมล/พื้นที่ดิสก์ · SFTP แบบ chroot

เมลจริงบนเครื่อง

กล่องจดหมายจริง (Postfix + Dovecot) อ่านผ่าน IMAP ได้ · โควตารายกล่อง · ตัวส่งต่อ · เซ็น DKIM ด้วย rspamd · ดูคิวขาออกและหัวเมลได้โดยไม่มาร์คว่าอ่านแล้ว

สำรองข้อมูล

ตั้งเวลาสำรองอัตโนมัติ · ส่งออกนอกเครื่องผ่าน local / sftp / rsync / S3 · กู้คืนพร้อมตรวจ checksum

เฝ้าระวังระบบ

กราฟย้อนหลัง CPU / RAM / ดิสก์ · เกณฑ์แจ้งเตือน · ส่งแจ้งเตือนทาง Email / Telegram / Webhook · เมตริกสดส่งมาแบบ SSE

ศูนย์ความปลอดภัย

Rate limit รายเว็บผ่าน fail2ban · firewall (ufw) · audit log แบบ hash-chain · ใบรับรอง TLS ของหน้าจัดการเองพร้อมต่ออายุอัตโนมัติ

แก้ไฟล์ตั้งค่าจากหน้าเว็บ

แก้ไฟล์ส่วนเสริมของ Apache / nginx / Postfix / Dovecot / BIND9 ได้เอง — ตรวจด้วยตัวตรวจของบริการนั้นก่อนใช้เสมอ ไม่ผ่านคืนค่าเดิมให้เอง

เครื่องมือระบบ

จัดการบริการและงานตามเวลา · ตัวจัดการไฟล์ · ตั้งค่า SSH · อัปเดตตัวเองโดยตรวจลายเซ็นก่อนติดตั้งทุกครั้ง

REST API และ CLI

REST API v2 แบบ JSON ล้วน (สเปก OpenAPI) · คำสั่ง phpcp สำหรับสถานะ ตรวจสุขภาพ ผู้ใช้ และตรวจ audit log

Architecture

ออกแบบให้ถูกยึดแล้ว…ก็ยึดได้แค่นั้น

Control panel คือเป้าหมายที่มีค่าที่สุดบนเซิร์ฟเวอร์ — BluPanel จึงแยกสิทธิ์เป็นสามชั้น และบังคับใช้ทุกการทำงานผ่านจุดตรวจเดียว

ชั้นที่ 1เว็บ API — ผู้ใช้ phpcp-web ไม่มี sudo ไม่มี shell
SPA บน Now.js คุยกับ /api/v2/* ที่ตอบ JSON ล้วน · Router + Middleware: Auth · CSRF · RBAC · RateLimit · เก็บ state ใน SQLite (WAL)

unix socket 0660 · /run/phpcp/agent.sock

ตรวจชนิดข้อมูลทุก argument · สั่งงานด้วย proc_open(argv[]) ไม่ผ่าน shell · ทำงานเป็นเจ้าของเว็บด้วย privilege drop · งานยาวเป็น job (backup / SSL / ติดตั้ง)

ชั้นเว็บไม่มีสิทธิ์ root เด็ดขาด

ช่องโหว่ใน UI ต้องไม่กลายเป็น root shell — ยึดชั้นเว็บได้ ก็อ่านไฟล์ระบบไม่ได้

ตัด command injection ที่ต้นทาง

เอเจนต์รับเฉพาะ capability แบบ typed ที่ลงทะเบียนไว้ ไม่ใช่คำสั่งอิสระ — กันเชิงโครงสร้าง ไม่ใช่ด้วยการ escape

ตรวจ config ก่อน reload ทุกครั้ง

ทุกการเขียนไฟล์ตั้งค่าผ่าน ConfigTransaction — เขียนแล้วตรวจ (apache2 -t, named-checkzone, sshd -t) ก่อน reload เสมอ ไม่ผ่านคือย้อนกลับอัตโนมัติ

panel มี stack ของตัวเอง

config tree ของตัวเองที่ /etc/phpcp พร้อม Apache และ PHP-FPM แยก — ไม่เขียนอะไรลง /etc/apache2 หรือ /etc/php แม้แต่ไฟล์เดียว สั่งหยุด Apache ของระบบแล้ว panel ยังต้องเข้าได้

state เก็บใน SQLite ไม่พึ่ง MariaDB

panel เป็นคนคุม MariaDB จึงห้ามพึ่งพามัน — MariaDB ล่มแล้ว panel ต้องยังเข้าได้เพื่อกดสั่ง start กลับ

3 โหมด: production · sandbox · dryrun

ทดสอบเต็มรูปแบบบนเครื่องนักพัฒนาได้โดยไม่แตะระบบจริง — ชุดทดสอบทั้งหมดรันโดยไม่ต้องใช้ root

Security

ความปลอดภัยเป็นสถาปัตยกรรม ไม่ใช่ช่องในเช็กลิสต์

มี threat model ที่เขียนไว้เป็นลายลักษณ์อักษร ระบุผู้โจมตี 5 ระดับที่ต้องรับมือ ตั้งแต่คนนอกที่ยังไม่ล็อกอิน จนถึง supply chain — พร้อมรายการตรวจก่อนขึ้น production

HTTPS เท่านั้น + HSTS บนพอร์ตแยก 8443ไม่มี default password — รหัสชั่วคราวสุ่มให้แสดงครั้งเดียว แล้วบังคับเปลี่ยนตั้งแต่ล็อกอินแรก
Argon2id + ตรวจรายการรหัสยอดนิยมเก็บรหัสผ่านด้วย Argon2id (64 MB memory cost) และปฏิเสธรหัสจากรายการ 10,000 อันดับที่ถูกแฮ็กบ่อย — ตรวจจากไฟล์ local ไม่ส่งออกเน็ต
2FA แบบ TOTP บังคับสำหรับผู้ดูแลsuperadmin และ sysadmin ต้องเปิด 2FA เสมอ · secret เข้ารหัสด้วย sodium secretbox · มี recovery code ใช้ได้ครั้งเดียว 10 ชุด
Rate limit + ล็อกบัญชีแบบทวีคูณtoken bucket ต่อ IP และต่อบัญชี · ผิด 5 ครั้งล็อก 15 นาที ผิดต่อเพิ่มเป็นชั่วโมง · ตอบเหมือนกันเสมอ กัน user enumeration
Session ผูก IP · คุกกี้ __Host- · หมุน id ทุก 15 นาทีเก็บเฉพาะ hash ของ session id · Secure · HttpOnly · SameSite=Strict · idle timeout 30 นาที และหมุน id ทันทีหลังล็อกอิน
CSP เข้มงวด ไม่มี unsafe-eval ไม่มี CDNscript-src ใช้ nonce ต่อ request · ไลบรารีฝั่งหน้าเว็บ commit เข้า repo พร้อม SHA256SUMS ที่ phpcp doctor ตรวจทุกครั้ง
Audit log แบบ hash-chainทุกการกระทำสำคัญถูกบันทึกเป็นลูกโซ่ hash ตรวจความต่อเนื่องย้อนหลังได้ด้วย phpcp audit:verify — ลบร่องรอยทำได้ยาก
แยกลูกค้าด้วย uid ต่อบัญชี + SFTP chrootลูกค้าโดนแฮ็กหนึ่งราย ต้องอ่านไฟล์ของอีกรายไม่ได้ — โควตาและสิทธิ์ผูกกับบัญชี ไม่ใช่เว็บไซต์
พบช่องโหว่? อย่าเปิด issue สาธารณะ — ใช้แท็บ Security → Report a vulnerability ของ repository ครับ · อ่าน เอกสารความปลอดภัย ให้จบก่อนเปิดใช้งานจริง
Get started

ติดตั้งบนเครื่องเปล่าด้วยคำสั่งเดียว

ตัวติดตั้งลงและตั้งค่าทั้งก้อนให้เอง — Apache, nginx, MariaDB, BIND9, Postfix, Dovecot, certbot, fail2ban, ufw, phpMyAdmin, logrotate และปิดเป็นรายข้อได้ถ้าเครื่องมีอยู่แล้ว

1

โคลน repository

ได้จาก GitHub ภายใต้สัญญาอนุญาต MIT

git clone https://github.com/goragodwiriya/blupanel.git && cd blupanel
2

รันตัวติดตั้ง

ปลายทางของการติดตั้งจะแสดงรหัสผ่านชั่วคราวของผู้ดูแล — แสดงครั้งเดียว จดไว้ให้ดี

sudo ./install.sh
3

เปิดหน้าจัดการ

ระบบบังคับเปลี่ยนรหัสผ่านตั้งแต่ล็อกอินครั้งแรก จากนั้นสร้างเว็บไซต์แรกพร้อม HTTPS ได้เลย

https://<server-ip>:8443

ความต้องการของระบบ

  • ระบบปฏิบัติการDebian 12+ · Ubuntu 22.04+ · Linux Mint 21+
  • PHP 8.2+PHP เท่านั้น ไม่มี Composer — ตัวติดตั้งลง PHP 8.4 ให้เอง
  • ทรัพยากรRAM 1 GB · ดิสก์ว่าง 10 GB · สิทธิ์ root
  • ทางเลือกสำหรับนักพัฒนา./install.sh --mode=sandbox --portable — ทดลองในโฟลเดอร์โปรเจ็กต์ ไม่ต้องใช้ root
'ทดสอบ "ติดตั้งบนเครื่องเปล่า" จริงใน CI ด้วย Docker ทุก push บน Debian 12, Ubuntu 22.04 และ 24.04 — ถ้าตัวติดตั้งพัง build จะล้ม · ติดตั้งบน AWS Lightsail มี คู่มือแยก'

ทำงานกับ CLI ได้ทั้งหมด

เหมาะกับ ssh เข้าไปดูเร็ว ๆ หรือเขียนสคริปต์ครอบทุกอย่าง

phpcp statusสถานะระบบโดยรวมในภาพเดียว
phpcp doctorตรวจสิทธิ์ ไฟล์ตั้งค่า scheduler และ checksum ของไลบรารี
phpcp-scheduler --listงานตามเวลาและผลรอบล่าสุด
phpcp audit:verifyตรวจความต่อเนื่องของ hash-chain ใน audit log
