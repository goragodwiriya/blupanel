# ติดตั้ง BluPanel บน AWS Lightsail

คู่มือนี้พาไปตั้งแต่ยังไม่มีเครื่อง จนถึงเปิดเว็บพร้อม HTTPS และส่งเมลออกได้จริง

Lightsail ต่างจาก VPS ทั่วไปในสามเรื่องที่ทำให้คนติดตั้งพลาดบ่อยที่สุด — **ไฟร์วอลล์สองชั้น**,
**พอร์ต 25 ถูกปิดจากฝั่ง AWS**, และ **ไม่มี swap มาให้** · ทั้งสามข้อมีอยู่ในคู่มือนี้ตามลำดับ
ที่ต้องทำจริง ไม่ใช่รวมไว้ท้ายเล่ม

> ติดตั้งบน VPS ทั่วไปหรือเครื่องของตัวเอง ให้ดู [INSTALL.md](INSTALL.md) แทน — สั้นกว่ามาก
> เพราะไม่ต้องยุ่งกับข้อจำกัดเฉพาะของ AWS

## สรุปก่อนเริ่ม — ค่าใช้จ่ายและเวลา

| สิ่งที่ต้องเตรียม | รายละเอียด |
|---|---|
| บัญชี AWS | ต้องผูกบัตรแล้ว · Lightsail คิดเงินรายเดือนแบบคงที่ |
| ชื่อโดเมน | จดที่ไหนก็ได้ ต้องแก้เนมเซิร์ฟเวอร์หรือเรกคอร์ดได้ |
| เวลา | ~30 นาที ถ้าไม่ทำเมล · ~1–3 วันถ้าทำเมล (รอ AWS อนุมัติพอร์ต 25) |
| ความรู้ที่ต้องมี | ใช้ SSH ได้ · แก้ DNS ที่ผู้รับจดโดเมนได้ |

## 1. เลือกขนาดเครื่อง — อย่าเลือกเล็กเกินไป

ตัวติดตั้งลง **PHP-FPM สองรุ่น (7.4 และ 8.4) · Apache · nginx · MariaDB · BIND9 · Postfix ·
Dovecot · rspamd · fail2ban · phpMyAdmin** ทั้งหมดรันพร้อมกัน

| แผน Lightsail | ใช้ได้ไหม | หมายเหตุ |
|---|---|---|
| 512 MB | **ไม่ได้** | MariaDB กับ rspamd อย่างเดียวก็เกินแล้ว ติดตั้งจะค้างหรือถูก OOM killer ฆ่ากลางคัน |
| 1 GB | ได้แบบจำกัด | ต้องมี swap · ปิดเมล (`--no-postfix`) · เหมาะกับเว็บเดียวที่คนเข้าไม่เยอะ |
| **2 GB** | **แนะนำขั้นต่ำ** | เว็บ 3–5 เว็บ พร้อมเมล · ยังต้องมี swap |
| 4 GB ขึ้นไป | สบาย | ขายโฮสติ้งให้ลูกค้าหลายราย |

**หน่วยความจำที่ขาดไม่ได้ยากกว่าดิสก์ที่เต็ม** — ดิสก์เต็มมีข้อความบอก แต่ RAM หมดคือโปรเซส
ถูกฆ่าแบบสุ่มโดยไม่มีอะไรฟ้อง แล้วอาการที่เห็นคือ "บางครั้งเว็บก็ล่ม"

## 2. สร้าง instance

1. เข้า [Lightsail console](https://lightsail.aws.amazon.com/) → **Create instance**
2. **Region** — เลือกใกล้ผู้ใช้จริง (คนไทยเลือก `ap-southeast-1` สิงคโปร์ · `ap-southeast-7`
   กรุงเทพฯ ถ้ามีให้เลือกในบัญชีของคุณ)
3. **Platform: Linux/Unix**
4. **Blueprint: OS Only → Ubuntu 24.04 LTS**

   > **อย่าเลือก blueprint สำเร็จรูปอย่าง LAMP, WordPress หรือ Plesk** — พวกนั้นมี Apache กับ
   > MySQL ที่ตั้งค่าไว้คนละแบบติดมาแล้ว ตัวติดตั้งจะชนกับของเดิมและได้เครื่องที่ซ่อมยากกว่า
   > ติดตั้งใหม่ · เครื่องเปล่าคือสิ่งที่ตัวติดตั้งออกแบบมาให้

5. **SSH key pair** — สร้างใหม่แล้ว **ดาวน์โหลดไฟล์ `.pem` เก็บไว้** (ดาวน์โหลดได้ครั้งเดียว)
6. เลือกแผนตามตารางข้อ 1
7. ตั้งชื่อ instance แล้วกด **Create**

## 3. Static IP — ทำทันที ก่อนทำอย่างอื่น

ไอพีที่ Lightsail ให้มาตอนแรกเป็นแบบชั่วคราว **เปลี่ยนทุกครั้งที่ stop/start เครื่อง** ·
ถ้าชี้โดเมนไปที่ไอพีนั้นแล้ววันหนึ่งรีสตาร์ต เว็บทั้งหมดจะหายไปพร้อมกันโดยไม่มีอะไรเตือน

1. **Networking** → **Create static IP**
2. เลือก region เดียวกับ instance → attach เข้ากับ instance
3. จดไอพีไว้ — จะใช้ตลอดทั้งคู่มือ (เรียกว่า `<STATIC_IP>`)

> static IP **ไม่มีค่าใช้จ่าย**ตราบใดที่ยังผูกกับ instance ที่เปิดอยู่ · ถ้าปล่อยว่างไว้
> เฉย ๆ จะถูกคิดเงิน

## 4. เปิดพอร์ตในไฟร์วอลล์ของ Lightsail

**นี่คือจุดที่คนพลาดมากที่สุด** — เครื่องมีไฟร์วอลล์ **สองชั้น**:

```
อินเทอร์เน็ต → ไฟร์วอลล์ของ Lightsail (คอนโซล) → UFW บนเครื่อง (ตัวติดตั้งตั้งให้) → บริการ
```

ตัวติดตั้งตั้ง UFW ให้อัตโนมัติ แต่**แตะไฟร์วอลล์ของ Lightsail ไม่ได้** เพราะอยู่คนละชั้น
ที่ AWS ควบคุม · เปิดที่คอนโซลไม่ครบ = เข้าหน้าจัดการไม่ได้ ทั้งที่บนเครื่องทุกอย่างปกติดี

ไปที่ instance → **Networking** → **IPv4 Firewall** → **Add rule** ทีละข้อ:

| Application | Protocol | Port | เปิดเมื่อ |
|---|---|---|---|
| SSH | TCP | 22 | เปิดอยู่แล้ว — **จำกัดเป็นไอพีของคุณ** ถ้าไอพีคงที่ |
| HTTP | TCP | 80 | เสมอ (ต้องใช้ขอใบรับรอง Let's Encrypt) |
| HTTPS | TCP | 443 | เสมอ |
| Custom | TCP | **8443** | เสมอ — **หน้าจัดการอยู่ที่พอร์ตนี้** |
| Custom | TCP | 53 | เมื่อใช้ BIND9 เป็น DNS ของโดเมน |
| Custom | **UDP** | 53 | เมื่อใช้ BIND9 — **ต้องเปิดทั้ง TCP และ UDP** คำถาม DNS ปกติวิ่งบน UDP |
| Custom | TCP | 25 | เมื่อทำเมล (รับเมลเข้า) |
| Custom | TCP | 465, 587 | เมื่อทำเมล (ให้ผู้ใช้ส่งเมลออก) |
| Custom | TCP | 993, 995 | เมื่อทำเมล (IMAP/POP3 over TLS) |

**ถ้าใช้ IPv6 ด้วย** ต้องเพิ่มกฎชุดเดียวกันในแท็บ **IPv6 Firewall** — เป็นคนละรายการกันสนิท
และเป็นสาเหตุคลาสสิกของอาการ "เข้าได้จากมือถือแต่ไม่ได้จากบ้าน"

> **จำกัด 8443 ให้เฉพาะไอพีของคุณถ้าทำได้** (ช่อง *Restrict to IP address*) · หน้าจัดการ
> มีการจำกัดอัตราและ 2FA อยู่แล้ว แต่การไม่เปิดให้ทั้งโลกเห็นย่อมดีกว่า

## 5. เชื่อมต่อและเตรียมเครื่อง

```bash
chmod 400 ~/Downloads/LightsailDefaultKey-ap-southeast-1.pem
ssh -i ~/Downloads/LightsailDefaultKey-ap-southeast-1.pem ubuntu@<STATIC_IP>
```

### 5.1 อัปเดตระบบ

```bash
sudo apt update && sudo apt full-upgrade -y
sudo reboot
```

รอสักครู่แล้ว ssh กลับเข้าไปใหม่

### 5.2 สร้าง swap — Lightsail ไม่มีมาให้

ไม่มี swap แปลว่า RAM เต็มเมื่อไร **เคอร์เนลฆ่าโปรเซสทิ้งทันที**ไม่มีการเตือน · MariaDB
กับ PHP-FPM เป็นเป้าแรกเสมอเพราะใช้หน่วยความจำมากที่สุด

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# ให้ใช้ swap เฉพาะตอนจำเป็นจริง ๆ ไม่ใช่ย้ายของที่ยังใช้อยู่ลงดิสก์
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf
sudo sysctl -p /etc/sysctl.d/99-swap.conf

free -h    # ต้องเห็นบรรทัด Swap มีขนาด 2.0Gi
```

หน้า **SERVER → เซิร์ฟเวอร์** ของ panel รายงานการใช้ swap ให้ดู — ถ้าเห็นว่าใช้เกินครึ่ง
เป็นประจำ แปลว่าถึงเวลาขยายแผนแล้ว ไม่ใช่เพิ่ม swap

### 5.3 ตั้งชื่อเครื่องให้เป็นชื่อจริง

**ทำก่อนติดตั้ง** — Postfix อ่านค่านี้ตอนติดตั้งเพื่อใช้เป็นชื่อผู้ส่ง และการแก้ทีหลัง
ต้องไล่แก้หลายไฟล์

```bash
sudo hostnamectl set-hostname panel.example.com
echo "<STATIC_IP> panel.example.com panel" | sudo tee -a /etc/hosts
hostname -f          # ต้องได้ panel.example.com
```

## 6. ตั้ง DNS ของโดเมน

เลือกทางใดทางหนึ่ง — **ทำก่อนติดตั้ง** เพราะการขอใบรับรอง Let's Encrypt ต้องให้โดเมนชี้มา
ที่เครื่องนี้แล้ว และ DNS ใช้เวลากระจายตัว

### ทางที่ 1 — ให้ Lightsail จัดการ DNS (ง่ายกว่า แนะนำสำหรับคนเริ่มต้น)

1. Lightsail → **Networking** → **Create DNS zone** → ใส่ชื่อโดเมน
2. เอาเนมเซิร์ฟเวอร์สี่ตัวที่ได้ไปตั้งที่ผู้รับจดโดเมน
3. สร้างเรกคอร์ดใน Lightsail:

   | Type | Name | Value |
   |---|---|---|
   | A | `@` | `<STATIC_IP>` |
   | A | `panel` | `<STATIC_IP>` |
   | A | `www` | `<STATIC_IP>` |

4. ตอนติดตั้ง **ไม่ต้องเปิด** `dns.enabled` ใน panel · ไม่ต้องเปิดพอร์ต 53

### ทางที่ 2 — ให้ BIND9 บนเครื่องเป็น DNS เอง

ได้ประโยชน์คือแก้เรกคอร์ดจากหน้า panel ได้เลย และเป็นสิ่งที่ต้องมีถ้าจะขายโฮสติ้งให้ลูกค้า

1. ที่ผู้รับจดโดเมน สร้าง **glue record** ชี้ `ns1.example.com` และ `ns2.example.com`
   ไปที่ `<STATIC_IP>` แล้วตั้งเนมเซิร์ฟเวอร์ของโดเมนเป็นสองชื่อนี้
2. เปิดพอร์ต **53 ทั้ง TCP และ UDP** ในไฟร์วอลล์ Lightsail (ข้อ 4)
3. หลังติดตั้ง เข้าหน้า **SERVER → ตั้งค่า** → เปิด **DNS (BIND9)** แล้วใส่เนมเซิร์ฟเวอร์
   ทั้งสองชื่อกับอีเมลผู้ดูแล DNS

   > **คำเตือนที่ต้องอ่านก่อนเปิด:** panel จัดการไฟล์ `named.conf.local` **ทั้งไฟล์** ·
   > zone ที่คุณเคยตั้งเองด้วยมือในไฟล์นั้นจะถูกเขียนทับหายไป

4. เนมเซิร์ฟเวอร์สองชื่อชี้ไอพีเดียวกันใช้งานได้จริง แต่ **ไม่มีความทนทาน** — เครื่องล่ม
   ทีเดียวคือ DNS ของทุกโดเมนหายพร้อมกัน · ถ้าขายโฮสติ้งจริงควรมีเครื่องที่สองเป็น secondary
   (ตั้ง `allow-transfer` ได้ในไฟล์ตั้งค่าเพิ่มเติมของ BIND9 ในหน้าโดเมน)

## 7. ติดตั้ง

```bash
sudo apt install -y git
git clone https://github.com/goragodwiriya/blupanel.git
cd blupanel
sudo ./install.sh
```

ใช้เวลาราว 5–15 นาทีตามความเร็วเครื่อง · ตัวติดตั้งจะบอกทุกขั้นตอนที่ทำ

**ไม่ทำเมล** (เบากว่ามาก เหมาะกับเครื่อง 1 GB):

```bash
sudo ./install.sh --no-postfix
```

### สิ่งที่ต้องทำทันทีเมื่อติดตั้งเสร็จ

ตอนจบตัวติดตั้งพิมพ์ **รหัสผ่านชั่วคราวของผู้ดูแล** ออกมา — **คัดลอกเก็บทันที แสดงครั้งเดียว
เท่านั้น** · ถ้าพลาดไปแล้วยังกู้ได้ด้วย `sudo phpcp user:passwd admin`

```bash
sudo phpcp status     # ทุกบริการต้องเขียว
sudo phpcp doctor     # ตรวจสิทธิ์ไฟล์และค่าตั้งที่ผิด
```

เปิดเบราว์เซอร์ไปที่ **`https://<STATIC_IP>:8443`**

เบราว์เซอร์จะเตือนเรื่องใบรับรอง — **ถูกต้องแล้ว** เพราะยังเป็นใบที่เครื่องเซ็นเอง
กด "ดำเนินการต่อ" ได้ · จะเปลี่ยนเป็นใบจริงในข้อ 9

## 8. ตั้งค่าความปลอดภัยทันทีที่เข้าได้

เรียงตามลำดับที่ควรทำ:

1. **เปลี่ยนรหัสผ่าน** — ระบบบังคับตั้งแต่เข้าครั้งแรกอยู่แล้ว
2. **เปิด 2FA** ที่หน้าบัญชีของคุณ · หน้าจัดการเปิดอยู่บนอินเทอร์เน็ต รหัสผ่านอย่างเดียวไม่พอ
3. เข้าหน้า **SERVER → ความปลอดภัย** แล้วไล่แก้ทุกข้อที่ขึ้นเป็นสีแดง
4. **ปิดการล็อกอิน SSH ด้วยรหัสผ่าน** (Lightsail ปิดมาให้แล้ว ตรวจซ้ำที่หน้า SSH ของ panel)
5. **จำกัดไอพีที่เข้าหน้าจัดการได้** ถ้าคุณเข้าจากที่เดียวเป็นประจำ

   ```bash
   sudo nano /etc/phpcp/config.php     # คีย์ panel.ip_allowlist
   ```

6. เปิด **automatic snapshots** ใน Lightsail (instance → Snapshots → Enable automatic snapshots)
   — คนละเรื่องกับการสำรองข้อมูลของ panel และควรมีทั้งคู่

## 9. ใบรับรองจริงสำหรับหน้าจัดการ

ต้องให้ `panel.example.com` ชี้มาที่ `<STATIC_IP>` แล้ว และพอร์ต 80 เปิดอยู่

ตรวจก่อนว่า DNS กระจายตัวแล้วจริง:

```bash
dig +short panel.example.com     # ต้องได้ <STATIC_IP>
```

### 9.1 ขอใบรับรอง

ในหน้า panel:

1. **เว็บไซต์ → สร้างเว็บไซต์** ด้วยโดเมน `panel.example.com`
2. เข้าหน้าเว็บนั้น → แท็บ **SSL** → **ขอใบรับรอง**

ได้ใบรับรองไว้ที่ `/etc/letsencrypt/live/panel.example.com/` แล้ว

### 9.2 ให้หน้าจัดการใช้ใบนั้น — ต้องทำด้วยมือ

> **ข้อจำกัดที่ต้องรู้:** ตอนนี้ยังไม่มีปุ่มในหน้าเว็บสำหรับเปลี่ยนใบรับรองของ*ตัวหน้าจัดการเอง*
> · หน้าจัดการอ่านไฟล์ที่ `/etc/phpcp/tls/panel.crt` กับ `panel.key` เสมอ ซึ่งตัวติดตั้ง
> สร้างเป็นใบเซ็นเองไว้ให้ตอนแรก

ชี้ไฟล์ทั้งสองไปที่ใบจริงด้วย symlink — ใช้ symlink ไม่ใช่ copy เพราะ certbot ต่ออายุใบทุก
60 วันโดยเขียนไฟล์ใหม่ในที่เดิม การ copy จะทำให้หน้าจัดการใช้ใบเก่าที่หมดอายุต่อไปเงียบ ๆ:

```bash
sudo mv /etc/phpcp/tls/panel.crt /etc/phpcp/tls/panel.crt.selfsigned
sudo mv /etc/phpcp/tls/panel.key /etc/phpcp/tls/panel.key.selfsigned

sudo ln -s /etc/letsencrypt/live/panel.example.com/fullchain.pem /etc/phpcp/tls/panel.crt
sudo ln -s /etc/letsencrypt/live/panel.example.com/privkey.pem   /etc/phpcp/tls/panel.key

sudo systemctl restart phpcp-web
```

**ต้องให้ Apache ของหน้าจัดการโหลดใบใหม่หลังต่ออายุด้วย** ไม่งั้นอีก 60 วันจะกลับไปเจอ
คำเตือนอีก ทั้งที่ใบบนดิสก์ถูกต้อง:

```bash
sudo mkdir -p /etc/letsencrypt/renewal-hooks/deploy
printf '#!/bin/sh\nsystemctl restart phpcp-web\n' \
  | sudo tee /etc/letsencrypt/renewal-hooks/deploy/phpcp-web.sh
sudo chmod +x /etc/letsencrypt/renewal-hooks/deploy/phpcp-web.sh
```

ตรวจว่าได้ผลจริง:

```bash
echo | openssl s_client -connect panel.example.com:8443 -servername panel.example.com 2>/dev/null \
  | openssl x509 -noout -issuer -dates
```

ต้องเห็น `issuer=C = US, O = Let's Encrypt` ไม่ใช่ชื่อของเครื่องเอง

เข้าที่ `https://panel.example.com:8443` ได้โดยไม่มีคำเตือนแล้ว

## 10. เมล — ข้อจำกัดของ AWS ที่ต้องจัดการก่อน

**ข้ามข้อนี้ได้ถ้าไม่ทำเมล** · แต่ถ้าจะทำ ต้องทำครบทุกข้อ ไม่งั้นเมลจะออกไปแล้วเข้าถังขยะ
หรือถูกปฏิเสธทิ้งเงียบ ๆ

### 10.1 ขอปลดล็อกพอร์ต 25 — ต้องทำก่อน ไม่มีทางลัด

**AWS ปิดการส่งออกพอร์ต 25 ของทุกบัญชีใหม่โดยปริยาย** เพื่อกันสแปม · ไม่ปลดล็อกก่อน
เมลจะส่งออกไม่ได้เลย ทั้งที่ทุกอย่างบนเครื่องถูกต้อง

1. เปิดแบบฟอร์ม **Request to remove email sending limitations** ของ AWS
   (`https://console.aws.amazon.com/support/contacts#/rdns-limits`) · ถ้าลิงก์เปลี่ยนไป
   ให้เข้า AWS Support Center แล้วค้นคำว่า *email sending limitations*
2. กรอกให้ครบ: static IP · ชื่อโดเมน · ใช้ส่งอะไร (เมลของลูกค้าโฮสติ้ง ไม่ใช่การตลาด) ·
   จัดการการยกเลิกรับเมลอย่างไร
3. **ขอ reverse DNS (PTR) ไปพร้อมกันในฟอร์มเดียวกัน** — ฟอร์มนี้มีช่องให้กรอก rDNS อยู่แล้ว
   ระบุว่าต้องการให้ `<STATIC_IP>` ชี้กลับเป็น `mail.example.com`

   **PTR สำคัญพอ ๆ กับพอร์ต 25** — เซิร์ฟเวอร์เมลปลายทางส่วนใหญ่ปฏิเสธเมลจากไอพีที่ไม่มี
   PTR หรือ PTR ไม่ตรงกับชื่อที่ประกาศตอน HELO

รออนุมัติปกติ **1–2 วันทำการ**

### 10.2 หลังได้รับอนุมัติ

```bash
sudo phpcp mail:enable example.com
sudo phpcp mail:box-add me@example.com --quota=2048
```

หรือทำจากหน้า **เมล** ใน panel ก็ได้

### 10.3 เรกคอร์ด DNS ที่ต้องมีครบ — ขาดข้อใดข้อหนึ่งเมลเข้าถังขยะ

| ชนิด | ชื่อ | ค่า | หน้าที่ |
|---|---|---|---|
| A | `mail` | `<STATIC_IP>` | ชื่อของเซิร์ฟเวอร์เมล |
| MX | `@` | `10 mail.example.com.` | บอกว่าเมลของโดเมนนี้ส่งไปที่ไหน |
| TXT | `@` | `v=spf1 mx -all` | ประกาศว่าเครื่องไหนส่งเมลแทนโดเมนนี้ได้ |
| TXT | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:postmaster@example.com` | บอกปลายทางว่าให้ทำอย่างไรกับเมลที่ตรวจไม่ผ่าน |
| TXT | `<selector>._domainkey` | ค่าที่ rspamd สร้างให้ | ลายเซ็น DKIM |

**panel สร้าง DKIM ให้เองตอนเปิดเมลของโดเมน** — ถ้าโดเมนนั้นใช้ DNS ของเครื่องนี้
(ทางที่ 2 ในข้อ 6) เรกคอร์ดทั้งหมดในตารางข้างบนถูกเพิ่มให้อัตโนมัติ ไม่ต้องทำอะไรเพิ่ม

ถ้าใช้ DNS ที่อื่น (ทางที่ 1) **panel แสดงค่าที่ต้องไปใส่เองให้ดูตอนเปิดเมล** — คัดลอกไปวาง
ที่ผู้ให้บริการ DNS · ดูซ้ำได้ที่หน้า **เมล** ของโดเมนนั้น

**ตรวจว่าผ่านจริงก่อนใช้งาน** — ส่งเมลจากกล่องที่สร้างไปหา Gmail แล้วเปิด
*แสดงต้นฉบับ* ต้องเห็น `SPF: PASS` · `DKIM: PASS` · `DMARC: PASS` ครบทั้งสามบรรทัด ·
เห็นไม่ครบแปลว่ายังไม่พร้อมใช้งานจริง ไม่ว่าเมลฉบับนั้นจะเข้ากล่องหรือไม่

## 11. สำรองข้อมูล — ต้องมีสองชั้น

**Lightsail snapshot** สำรองทั้งเครื่อง กู้กลับได้ทั้งก้อน แต่กู้ไฟล์เดียวไม่ได้และอยู่ใน
บัญชี AWS เดียวกัน

**การสำรองของ panel** สำรองรายเว็บ กู้ทีละไฟล์ได้ และ **ส่งออกไปนอกเครื่องได้**

ตั้งปลายทางนอกเครื่องที่หน้า **สำรองข้อมูล → ปลายทาง** — รองรับ S3 (รวมถึงบริการที่เข้ากันได้
อย่าง Backblaze B2, Cloudflare R2, MinIO), SFTP และ rsync

> **ไฟล์สำรองที่อยู่บนเครื่องเดียวกันหายไปพร้อมดิสก์ก้อนนั้น** — ตั้งปลายทางนอกเครื่องเสมอ

## 12. แก้ปัญหาที่พบบ่อยบน Lightsail

### เข้า `https://<STATIC_IP>:8443` ไม่ได้เลย

ไล่จากนอกเข้าใน:

```bash
# 1. บริการทำงานอยู่ไหม
sudo systemctl status phpcp-web phpcp-fpm phpcp-agentd

# 2. เครื่องฟังพอร์ตนั้นอยู่จริงไหม
sudo ss -ltnp | grep 8443

# 3. UFW บนเครื่องเปิดไหม
sudo ufw status | grep 8443

# 4. เข้าจากในเครื่องเองได้ไหม
curl -k https://127.0.0.1:8443/ -o /dev/null -w '%{http_code}\n'
```

ทั้งสี่ข้อผ่านแต่ยังเข้าจากข้างนอกไม่ได้ = **ไฟร์วอลล์ของ Lightsail ยังไม่ได้เปิด 8443**
(ข้อ 4 ของคู่มือนี้) — เป็นสาเหตุของกรณีนี้เกือบทุกครั้ง

### ติดตั้งค้างหรือหลุดกลางคัน

RAM ไม่พอ · ตรวจว่ามีการฆ่าโปรเซสไหม:

```bash
sudo dmesg | grep -i 'killed process'
free -h
```

เจอ = ทำ swap ตามข้อ 5.2 แล้วรัน `sudo ./install.sh` ซ้ำได้ (ตัวติดตั้งรันซ้ำได้อย่างปลอดภัย)

### ขอใบรับรอง Let's Encrypt ไม่ผ่าน

```bash
dig +short panel.example.com          # ต้องได้ <STATIC_IP>
curl -I http://panel.example.com/     # ต้องไม่ timeout
```

DNS ยังไม่ตรง = รอให้กระจายตัวก่อน · timeout = พอร์ต 80 ยังไม่เปิดในไฟร์วอลล์ Lightsail

### เมลส่งออกไม่ได้

```bash
sudo phpcp status
mailq                                  # มีค้างในคิวไหม
sudo tail -50 /var/log/mail.log
```

เห็น `Connection timed out` ไปพอร์ต 25 = **AWS ยังไม่ปลดล็อก** (ข้อ 10.1) ·
ดูคิวและกดดำเนินการซ้ำได้ที่หน้า **เมล → คิวขาออก** ของ panel

### เว็บช้าลงเรื่อย ๆ

ดูหน้า **SERVER → เซิร์ฟเวอร์** — ถ้า swap ถูกใช้เกินครึ่งเป็นประจำ แปลว่า RAM ไม่พอจริง
Lightsail เปลี่ยนแผนได้จาก snapshot: สร้าง snapshot → สร้าง instance ใหม่จาก snapshot ด้วย
แผนที่ใหญ่ขึ้น → ย้าย static IP ไปเครื่องใหม่

## 13. รายการตรวจก่อนเปิดใช้งานจริง

- [ ] static IP ผูกกับ instance แล้ว
- [ ] ไฟร์วอลล์ Lightsail เปิด 80, 443, 8443 (และ 53 TCP+UDP ถ้าใช้ BIND9)
- [ ] กฎ IPv6 ตั้งครบเหมือน IPv4 (ถ้าใช้ IPv6)
- [ ] swap ทำงานอยู่ — `free -h`
- [ ] `sudo phpcp status` เขียวทุกบรรทัด
- [ ] `sudo phpcp doctor` ไม่มีข้อผิดพลาด
- [ ] เปลี่ยนรหัสผ่านผู้ดูแลและเปิด 2FA แล้ว
- [ ] หน้าจัดการใช้ใบรับรองจริง ไม่ใช่ใบที่เซ็นเอง
- [ ] หน้า SERVER → ความปลอดภัย ไม่มีข้อสีแดงค้าง
- [ ] เปิด automatic snapshots ใน Lightsail แล้ว
- [ ] ตั้งปลายทางสำรองข้อมูลนอกเครื่องแล้ว และ**ทดลองกู้คืนสำเร็จอย่างน้อยหนึ่งครั้ง**
- [ ] (ถ้าทำเมล) AWS ปลดล็อกพอร์ต 25 และตั้ง PTR ให้แล้ว
- [ ] (ถ้าทำเมล) ส่งเมลไป Gmail แล้วได้ SPF/DKIM/DMARC ผ่านครบสามข้อ
