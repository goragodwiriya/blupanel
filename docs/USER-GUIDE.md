# คู่มือผู้ใช้

สำหรับผู้ที่ต้องดูแลเว็บไซต์บนเซิร์ฟเวอร์ผ่านหน้าจัดการนี้
ถ้ายังไม่ได้ติดตั้ง ดู [INSTALL.md](INSTALL.md) ก่อน

---

## 1. เข้าใจโครงสร้างของหน้าจัดการ

เมนูด้านซ้ายแบ่งเป็นสองหมวดที่**ไม่ปนกันเด็ดขาด**

| หมวด | ใช้ทำอะไร | ใครเห็น |
|---|---|---|
| **HOSTING** | จัดการเว็บไซต์ โดเมน ฐานข้อมูล ไฟล์ SSL งานอัตโนมัติ สำรองข้อมูล | ทุกคน |
| **SERVER** | จัดการเครื่อง — บริการ firewall SSH ผู้ใช้ระบบ log ความปลอดภัย | ผู้ดูแลเซิร์ฟเวอร์เท่านั้น |

เหตุผลที่แยก: การเปลี่ยนเวอร์ชัน PHP ของเว็บไซต์หนึ่งเว็บ กับการรีสตาร์ตบริการ PHP-FPM
ทั้งเครื่อง เป็นคนละเรื่องกันโดยสิ้นเชิง อย่างแรกกระทบเว็บเดียว อย่างที่สองกระทบทุกเว็บ
หน้าเว็บไซต์จึงบอกได้ว่า "PHP 8.4" แต่จะไม่มีปุ่มรีสตาร์ต PHP-FPM อยู่ตรงนั้น

### บทบาทผู้ใช้

| บทบาท | ทำอะไรได้ |
|---|---|
| **ผู้ดูแลระบบ** (superadmin) | ทุกอย่าง รวมถึงจัดการผู้ใช้คนอื่น |
| **ผู้ดูแลเซิร์ฟเวอร์** (sysadmin) | หมวด SERVER ทั้งหมด + ดูข้อมูลเว็บไซต์ได้แต่แก้ไม่ได้ |
| **ผู้ดูแลเว็บไซต์** (webadmin) | เฉพาะเว็บไซต์ของตัวเอง ไม่เห็นหมวด SERVER เลยแม้แต่หัวข้อ |

## 2. สร้างเว็บไซต์แรก

**เว็บไซต์ → สร้างเว็บไซต์** กรอกชื่อ โดเมน และเลือกเวอร์ชัน PHP

ระบบจะทำให้อัตโนมัติ:

- สร้างผู้ใช้ระบบแยกเฉพาะเว็บนี้ (`web_1`, `web_2`, …)
- สร้าง PHP-FPM pool ของตัวเองที่รันด้วยผู้ใช้นั้น
- ตั้ง `open_basedir` ให้เข้าถึงได้แค่โฟลเดอร์ของเว็บตัวเอง
- สร้างไฟล์ค่าตั้งของเว็บเซิร์ฟเวอร์แล้ว**ตรวจก่อนใช้งานจริง**

**เว็บไซต์แต่ละเว็บอ่านไฟล์ของกันและกันไม่ได้** เพราะรันคนละ uid และมี `open_basedir` กำกับ
ถ้าเว็บหนึ่งถูกเจาะ ความเสียหายไม่ลามไปเว็บอื่น

### ชี้โดเมนมาที่เซิร์ฟเวอร์

ก่อนใช้งานจริงต้องตั้ง DNS ให้ชี้มาที่ไอพีของเครื่องนี้ ตรวจด้วย:

```bash
dig +short example.com
```

ต้องได้ไอพีของเซิร์ฟเวอร์ ถ้ายังไม่ตรง **อย่าเพิ่งขอใบรับรอง SSL** เพราะจะล้มเหลว

---

## 3. ติดตั้ง SSL

**SSL Certificates** → กด **ติดตั้ง SSL** ที่แถวของเว็บไซต์

| วิธี | เหมาะกับ |
|---|---|
| **Let's Encrypt** | เว็บสาธารณะที่ชี้โดเมนมาแล้ว — ฟรี ต่ออายุอัตโนมัติ เบราว์เซอร์เชื่อถือ |
| **เซ็นเอง** | ทดสอบ หรือเว็บภายในที่ไม่มีชื่อโดเมนสาธารณะ — เบราว์เซอร์จะเตือนเสมอ |

จากนั้นกด **เปิดใช้งาน HTTPS** แล้วค่อยกด **บังคับ HTTPS** เมื่อแน่ใจว่าเว็บทำงานดีแล้ว

**"บังคับ HTTPS" คิดให้ดีก่อนกด** — ระบบจะส่ง header HSTS ที่เบราว์เซอร์จำไว้ 6 เดือน
ถ้าปิด HTTPS ทีหลัง คนที่เคยเข้าเว็บแล้วจะเข้าไม่ได้เลยจนกว่าจะครบกำหนด และแก้ที่เซิร์ฟเวอร์ไม่ได้

### ถ้าขอใบรับรองไม่ผ่าน

ระบบจะบอกสาเหตุเป็นภาษาไทยพร้อมทางแก้ สาเหตุที่พบบ่อย:

- **โดเมนยังไม่ชี้มา** — แก้ DNS แล้วรอให้แพร่กระจาย
- **พอร์ต 80 ปิดอยู่** — Let's Encrypt ต้องเรียกเข้ามาตรวจสอบทางพอร์ตนี้เท่านั้น
- **ขอบ่อยเกินโควตา** — ใช้โหมด staging ระหว่างที่ยังปรับแต่งอยู่ ไม่นับโควตา

### การต่ออายุ

ใบของ Let's Encrypt มีอายุ 90 วัน ระบบต่อให้อัตโนมัติเมื่อเหลือ 30 วัน
หน้า SSL จะเตือนถ้าตัวต่ออายุอัตโนมัติไม่ทำงาน — **อย่าเมินคำเตือนนั้น**

## 4. จัดการไฟล์

**ตัวจัดการไฟล์** ทำงานคล้าย File Explorer ของ Windows

- **ผู้ดูแลเว็บไซต์** เห็นเฉพาะไฟล์ของเว็บตัวเอง
- **ผู้ดูแลเซิร์ฟเวอร์** เข้าถึงได้ทั้งเครื่อง ยกเว้นไฟล์ของ panel เอง

ทำได้: อัปโหลด แก้ไข เปลี่ยนชื่อ ย้าย ลบ บีบอัด แตกไฟล์ เปลี่ยนสิทธิ์

**สิ่งที่ทำไม่ได้โดยเจตนา** — แตะไฟล์ของ panel เอง (`/usr/share/phpcp`, `/etc/phpcp`,
`/var/lib/phpcp`) เพราะฐานข้อมูลของ panel เก็บรหัสผ่านที่เข้ารหัสไว้และ session ของผู้ดูแล
ถ้าเปิดให้แก้ผ่านหน้าเว็บได้ ช่องโหว่เดียวในตัวจัดการไฟล์จะเท่ากับยึดเครื่องทั้งเครื่อง

---

## 5. ฐานข้อมูล

**ฐานข้อมูล → สร้างฐานข้อมูล** ระบบจะสร้างฐานข้อมูลพร้อมผู้ใช้และสุ่มรหัสผ่านให้

**รหัสผ่านจะแสดงครั้งเดียวเท่านั้น** คัดลอกเก็บทันที ระบบไม่เก็บไว้ในรูปที่อ่านกลับได้
ถ้าลืมให้ตั้งใหม่ ไม่ใช่ขอดูของเดิม

---

## 6. สำรองและกู้คืนข้อมูล

**สำรองข้อมูล** — สำรองได้ทั้งไฟล์เว็บไซต์ ฐานข้อมูล และค่าตั้งเซิร์ฟเวอร์

ทุกไฟล์สำรองมี checksum กำกับ ระบบตรวจก่อนกู้คืนทุกครั้ง
ไฟล์ที่ยืนยันความครบถ้วนไม่ได้จะถูกทำเครื่องหมายไว้ตั้งแต่ในรายการ **กู้คืนไม่ได้เลย**

**ตอนกู้คืน ระบบจะสำรองสถานะปัจจุบันไว้ให้ก่อนอัตโนมัติ** — ถ้ากู้ผิดไฟล์ยังย้อนกลับได้

> สำรองข้อมูลก่อนทำอะไรที่สำคัญเสมอ และ**ทดสอบกู้คืนจริงอย่างน้อยหนึ่งครั้ง**
> ข้อมูลสำรองที่ไม่เคยทดลองกู้ ไม่ต่างจากไม่มีข้อมูลสำรอง

## 7. เมล

**ต้องเปิดทีละโดเมน** — ติดตั้ง panel แล้วยังไม่รับเมลจนกว่าจะสั่งเปิดเอง

1. หน้า **เมล** → เลือกโดเมน → **เปิดเมลของโดเมนนี้**
2. panel สร้างกุญแจ DKIM ให้เอง และ**เพิ่มเรกคอร์ด DNS ที่จำเป็นให้ครบ**ถ้าโดเมนนั้นใช้
   DNS ของเครื่องนี้ · ถ้าใช้ DNS ที่อื่น หน้าจอจะแสดงค่าที่ต้องไปใส่เอง
3. **เพิ่มกล่องจดหมาย** พร้อมโควตาต่อกล่อง
4. **ตัวส่งต่อ** คือที่อยู่ที่ไม่มีกล่องจริงแต่ส่งทุกอย่างต่อไปที่อื่น · แถวที่มีแค่
   `@domain` รับทุกที่อยู่ที่ไม่ตรงกับกล่องไหนเลย

### ตั้งค่าโปรแกรมเมลของผู้ใช้

| ค่า | IMAP | SMTP |
|---|---|---|
| เซิร์ฟเวอร์ | ชื่อโฮสต์เมลของเครื่อง | ชื่อเดียวกัน |
| พอร์ต | 993 (SSL/TLS) | 587 (STARTTLS) หรือ 465 (SSL/TLS) |
| ชื่อผู้ใช้ | ที่อยู่อีเมลเต็ม | ที่อยู่อีเมลเต็ม |

### เมลส่งไม่ออกหรือเข้าถังขยะ

**ตรวจสามข้อนี้ก่อนอย่างอื่นเสมอ** — เกือบทุกกรณีอยู่ในนี้:

1. **SPF, DKIM, DMARC ผ่านครบไหม** — ส่งไป Gmail แล้วเปิด *แสดงต้นฉบับ* ต้องเห็น `PASS`
   ทั้งสามบรรทัด
2. **reverse DNS (PTR) ของไอพีตรงกับชื่อโฮสต์เมลไหม** — ผู้ให้บริการคลาวด์ส่วนใหญ่ต้องขอ
   ตั้งค่านี้เอง ไม่ได้ตั้งมาให้
3. **พอร์ต 25 ขาออกถูกปิดไหม** — AWS, Google Cloud และ Azure ปิดไว้โดยปริยายทุกบัญชี
   ต้องขอปลดล็อกก่อน

**คิวขาออก** ในหน้าเมลบอกว่ามีเมลค้างอยู่ไหมและค้างเพราะอะไร · เปิดดูหัวเมลและเนื้อความ
ได้จากตรงนั้น **โดยไม่ทำให้เมลถูกมาร์คว่าอ่านแล้ว** — ใช้ตอนไล่หาสาเหตุว่าทำไมเมลฉบับหนึ่ง
ไม่ถึงปลายทาง

## 8. DNS

หน้า **โดเมน** จัดการเรกคอร์ดของทุกโดเมนที่ใช้ BIND9 ของเครื่องนี้

### แก้ทีละรายการ

**เพิ่มเรกคอร์ด DNS** → เลือกชนิด ใส่ชื่อกับค่า · ช่องชนิด**พิมพ์เองได้** ไม่ได้จำกัดแค่
ตัวเลือกที่ขึ้นมาให้ — ใส่ `TLSA`, `SSHFP`, `DS` หรือชนิดอื่นได้ตามต้องการ

### แก้ทั้งชุดพร้อมกัน

**แก้เรกคอร์ดทั้งชุด** เปิดช่องข้อความแบบ zone file ให้แก้ทีเดียวหลายรายการ ·
จำเป็นเวลาย้ายเมลไปผู้ให้บริการอื่น ซึ่ง**ต้องลบ MX เดิมออกพร้อมกับใส่ของใหม่** ไม่งั้น
เมลจะวิ่งไปสองทาง

> **เป็นการแทนที่ทั้งชุด** — รายการที่ลบออกจากข้อความคือลบจริง · ตรวจทั้งรายการก่อนบันทึก
> ไม่ใช่แค่บรรทัดที่แก้

บันทึกแล้ว `named-checkzone` ตรวจก่อนเสมอ · ไม่ผ่านคือไม่มีอะไรเปลี่ยน และข้อความผิดพลาด
จะบอกหมายเลขบรรทัดที่มีปัญหา

### ดูไฟล์จริง

ปุ่ม **ไฟล์ zone** แสดงไฟล์ที่ BIND9 ใช้อยู่จริงบนดิสก์ **ไม่ใช่ค่าที่ประกอบใหม่จากตาราง** ·
ถ้าสองอย่างไม่ตรงกัน หน้าจอจะเตือนพร้อมบอกว่าต่างกันอย่างไร — กด **ซิงก์ zone ใหม่ทั้งหมด**
ในหน้ารายชื่อโดเมนเพื่อเขียนไฟล์ใหม่จากค่าในระบบ

## 9. ไฟล์ตั้งค่าของระบบ

สำหรับผู้ที่รู้ว่ากำลังทำอะไร — แก้ค่าที่ panel ไม่ได้เปิดให้ตั้งจากหน้าจอ

| หน้า | ไฟล์ที่แก้ได้ |
|---|---|
| เว็บไซต์ (แต่ละเว็บ) | ค่าเพิ่มเติมของ Apache หรือ nginx เฉพาะเว็บนั้น |
| เมล | ค่าเพิ่มเติมของ Postfix และ Dovecot |
| โดเมน | ค่าเพิ่มเติมของ BIND9 |

**กติกาเดียวกันทุกไฟล์:**

- ไฟล์ที่ panel สร้าง (vhost, `main.cf`, `named.conf.local`) **เปิดดูได้แต่แก้ไม่ได้** —
  มันถูกเขียนทับทั้งไฟล์ทุกครั้งที่มีคนแตะข้อมูลที่เกี่ยวข้อง การแก้จะหายไปเงียบ ๆ
- ไฟล์ส่วนเสริมเป็นของคุณล้วน panel ไม่แตะเลย และถูกอ่าน**ท้ายสุด** ค่าที่เขียนจึงชนะ
- เปิดครั้งแรกจะมี**คำอธิบายและตัวอย่างอยู่ในไฟล์**ให้แล้ว คอมเมนต์ไว้ทั้งหมด
- บันทึกแล้ว**ตัวตรวจของบริการนั้นเองตรวจก่อน** (`apachectl configtest`, `nginx -t`,
  `postfix check`, `doveconf -n`, `named-checkconf`) ไม่ผ่านคือคืนค่าเดิมทันที
- ผ่านแล้ว **ยังต้องกดยืนยันภายในเวลาที่กำหนด** — แถบนับถอยหลังจะขึ้นบนหน้าจอ ·
  ไม่กดยืนยันระบบคืนค่าเดิมให้เอง เพราะตัวตรวจไวยากรณ์ไม่ได้ตอบว่าเว็บยังใช้งานได้จริง

## 10. หมวด SERVER

### ความปลอดภัย

หน้านี้ให้คะแนน 0–100 พร้อมรายการสิ่งที่ควรทำ **เรียงตามผลกระทบ** ทุกข้อกดไปหน้าที่แก้ได้เลย

ตรวจจากสภาพจริงของเครื่องทุกครั้งที่เปิดหน้า ไม่ใช่จากค่าที่ระบบเคยบันทึกไว้

ข้อที่ระบบ **ตรวจไม่ได้** จะนับคะแนนเท่ากับยังไม่ผ่าน ไม่ใช่ข้ามไป —
เพราะถ้าข้ามได้ เครื่องที่เสียจนตรวจอะไรไม่ได้เลยจะได้ 100 คะแนน ซึ่งตรงข้ามกับความจริง

### Firewall

กฎที่เปิดพอร์ตของหน้าจัดการนี้และพอร์ต SSH **ถูกปักหมุดไว้ ลบไม่ได้** เพราะทำแล้วจะไม่มีทางกลับเข้ามาแก้

- กฎ **อนุญาต** มีผลทันที (เปิดพอร์ตเพิ่มไม่ทำให้เข้าเครื่องไม่ได้)
- กฎ **ปิดกั้น**, การ **ลบกฎ** และการ **เปิด firewall** ต้องกดยืนยันภายในเวลาที่กำหนด
  ไม่ยืนยัน = ระบบย้อนให้เองอัตโนมัติ

### SSH

แก้ได้ 5 ค่าเท่านั้น และค่าที่ใส่ได้ถูกจำกัดไว้ล่วงหน้า — ไม่เปิดให้แก้ไฟล์ทั้งไฟล์
เพราะ `sshd_config` ที่ผิดรูปแบบทำให้บริการ SSH ไม่ขึ้นเลย

ทุกครั้งที่บันทึก ระบบจะตรวจไฟล์ด้วย `sshd -t` ก่อน แล้วเริ่มนับถอยหลังรอการยืนยัน

> **วิธีใช้ที่ถูกต้อง:** กดบันทึก → เปิดหน้าต่างใหม่ → ลอง `ssh` เข้าเครื่องด้วยค่าใหม่
> → ถ้าเข้าได้ค่อยกดยืนยัน · ถ้าเข้าไม่ได้ ปล่อยให้หมดเวลา ระบบคืนค่าเดิมให้เอง

### บริการ

start / stop / restart / reload บริการของระบบได้

**บริการของ panel เองไม่อยู่ในรายการนี้** — สั่งได้จากบรรทัดคำสั่งเท่านั้น
เพราะการกดหยุดบริการของหน้าเว็บจากหน้าเว็บ คือการตัดขาตัวเอง

## 11. เมื่อเข้าหน้าจัดการไม่ได้

บรรทัดคำสั่งใช้ได้เสมอ ไม่ว่าหน้าเว็บจะเป็นอย่างไร

```bash
sudo phpcp status                          # ตรวจว่าส่วนไหนไม่ทำงาน
sudo phpcp doctor                          # ตรวจการตั้งค่าและสิทธิ์ที่ผิด
sudo phpcp user:passwd admin '<รหัสใหม่>'   # ตั้งรหัสผ่านใหม่
sudo phpcp user:disable-2fa admin          # ปิด 2FA กรณีทำอุปกรณ์หาย
sudo systemctl restart phpcp-web           # รีสตาร์ตหน้าจัดการ
```

## 12. ตรวจสอบย้อนหลัง

ทุกการกระทำที่เปลี่ยนแปลงระบบถูกบันทึกไว้ใน audit log พร้อมชื่อผู้ทำ ไอพี และเวลา

บันทึกเป็น **สายโซ่แฮช** — แก้ไขรายการเก่าโดยไม่ทิ้งร่องรอยไม่ได้ และ**ไม่มีคำสั่งลบ**

```bash
sudo phpcp audit:verify     # ตรวจว่าสายโซ่ยังต่อเนื่องครบ
```

ทุกคำสั่งถูกบันทึกสองครั้ง: ตอน "เริ่มดำเนินการ" พร้อมค่าที่ส่งเข้ามา และตอน "สำเร็จ"
ถ้าระบบล่มกลางคัน จะยังเหลือหลักฐานว่ากำลังทำอะไรอยู่
